# Часть 3. Многопоточная и многопроцессорная обработка данных

## Запуск

```bash
cd part3_parallel
python -m app.producer_consumer --path ../data/input --workers 2
python -m app.performance --path ../data/input --output ../data/output/performance_report.json
```

## Архитектура

- Один поток-производитель обходит каталог и кладёт пути к файлам в `queue.Queue`.
- Несколько потоков-потребителей читают изображения (Pillow, приведение к 32×32,
  нормализация на 255) и кладут массивы во вторую очередь.
- Пул процессов `multiprocessing.Pool` получает массивы, применяет аугментацию
  (повороты, отражения, добавление шума — функция `augment.py`) через `apply_async`.
- Общий счётчик обработанных файлов защищён `threading.Lock`.
- Каждому потребителю по завершении работы отправляется сигнал стопа; все потоки и
  процессы корректно завершаются (`pool.close()`, `pool.join()`, `thread.join()`).

## Замер времени

`app.performance` прогоняет последовательную и параллельную версии на одном наборе
файлов и сохраняет сравнение в `performance_report.json`: время обеих версий,
число файлов, число аугментированных массивов и ускорение.

Примечание: если в среде исполнения недоступны системные семафоры (некоторые
контейнеры), программа автоматически переключается на пул потоков с предупреждением
в консоли; на обычной рабочей машине используется пул процессов.
